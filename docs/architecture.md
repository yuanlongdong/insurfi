# InsurFi 架构设计文档

## 1. 系统总览

InsurFi 采用三层解耦架构：代币层 → 保险池层 → DApp 前端层。各层通过标准接口交互，支持独立升级和迭代。

## 2. 代币层（Token Layer）

### 2.1 INSUR 代币

- **标准**：BEP20 (BSC)
- **核心功能**：
  - 持仓快照（用于保单激活判定）
  - 持仓量分级映射（对应不同保额）
  - 转账/授权标准接口
- **特殊机制**：
  - 最小持仓阈值：低于阈值不激活保单
  - 持仓时间权重：持仓越久，保单系数越高（迭代）

### 2.2 持仓快照模块

- 采用区块号快照机制，记录用户在特定区块的持仓量
- 理赔时校验交易发生区块的持仓快照，确保参保有效性
- 防止「亏损后买入代币骗保」攻击

## 3. 保险池层（Insurance Pool Layer）

### 3.1 保险资金池（InsurancePool）

- **资金币种**：BNB（原生代币）
- **资金来源**：
  - 项目方初始注资
  - INSUR 交易税分红（迭代）
  - 流动性提供者存款（迭代）
- **核心功能**：
  - 资金存入/提取（权限控制）
  - 赔付支出（仅 LossVerifier 校验通过后）
  - 池余额查询、赔付历史记录
  - 偿付能力监控（池余额 / 待赔付总额）

### 3.2 亏损校验器（LossVerifier）

- **核心职责**：验证用户交易亏损的真实性和金额
- **校验流程**：
  1. 用户提交交易哈希（txHash）
  2. 校验交易是否在指定 DEX/合约接口发生
  3. 校验交易方向（买入/卖出）和代币对
  4. 计算交易亏损金额（对比入场价和出场价）
  5. 校验交易发生时用户是否持有有效保单
  6. 校验该交易未被重复理赔
- **防攻击**：
  - 交易哈希去重映射
  - 仅接受指定合约地址的交易事件
  - 亏损金额计算基于链上实际成交数据

### 3.3 保单管理器（PolicyManager）

- **核心职责**：管理用户保单状态和保额计算
- **保单状态**：
  - INACTIVE：持仓不足，未激活
  - ACTIVE：持仓达标，保单有效
  - SUSPENDED：异常暂停（如池资金不足）
- **保额计算**：
  - 基础保额 = f(INSUR持仓量)
  - 实际赔付 = min(实际亏损, 基础保额 × 保单系数)
  - 赔付比例：初期固定比例（如 50%），后期治理可调

### 3.4 DEX 适配器（DEXAdapter）

- **核心职责**：统一不同 DEX 的交易数据解析接口
- **支持 DEX**：
  - PancakeSwap（V2/V3）
  - Biswap
  - MDEX
  - 自定义合约接口（迭代）
- **接口标准**：
  - `parseTrade(txHash) → TradeInfo`
  - `getSupportedDEXs() → address[]`

## 4. DApp 前端层（Frontend Layer）

### 4.1 技术选型

- **框架**：Next.js 14 (App Router)
- **语言**：TypeScript
- **Web3**：wagmi + viem
- **样式**：Tailwind CSS + shadcn/ui
- **状态**：React Query + Zustand

### 4.2 核心模块

- **钱包连接**：MetaMask / WalletConnect / Binance Web3 Wallet
- **网络切换**：BSC Mainnet / Testnet 自动检测和切换
- **合约交互**：统一的合约调用 hook 封装
- **数据查询**：链上数据 + 子图（The Graph，迭代）

## 5. 合约交互流程

### 5.1 参保流程

```
用户持有 INSUR → 持仓快照记录 → PolicyManager 判定 → 保单自动激活
```

### 5.2 理赔流程

```
用户提交 txHash
    ↓
LossVerifier 校验交易有效性
    ↓
校验持仓快照（交易发生时保单有效）
    ↓
计算亏损金额和赔付金额
    ↓
InsurancePool 转账 BNB 到用户钱包
    ↓
记录赔付历史，标记 txHash 已理赔
```

### 5.3 资金注入流程

```
项目方/LP 存入 BNB → InsurancePool 接收 → 更新池余额 → 事件通知
```

## 6. 安全设计

### 6.1 访问控制

- 采用 Ownable2Step + AccessControl 双重权限
- 核心操作（资金提取、参数设置）需多签（迭代）

### 6.2 防重入

- 所有资金转出操作使用 ReentrancyGuard
- 遵循 Checks-Effects-Interactions 模式

### 6.3 防骗保

- 持仓快照机制（交易前已参保）
- 交易哈希去重
- 仅白名单 DEX 合约交易有效
- 单笔赔付上限 + 单用户累计赔付上限

### 6.4 紧急暂停

- Circuit Breaker 机制，异常时暂停赔付
- 暂停后仅允许资金提取（管理员），不允许新理赔

## 7. 升级策略

- 核心合约采用 UUPS 代理模式，支持逻辑升级
- 升级需 Timelock（24h 延迟）+ 多签确认
- 非核心合约（如 DEXAdapter）可独立部署替换
